# DigDeep — 2026.10.17-r5

[English](README.md) | Русский

## Что это и для какой цели

DigDeep — скилл для ИИ-ассистента, который помогает найти, как другие решали похожую задачу, проверить их опыт и выбрать подходящий следующий шаг. Он полезен в программировании, инженерии и других областях, где нужно разобраться в существующих методах, ограничениях и неудачных попытках.

Это набор инструкций и необязательный вспомогательный скрипт. Для поиска ассистент использует инструменты своей программы: веб-поиск, браузер, подключённые приложения и доступные публичные источники.

Версия r5 проверена в Claude Code (Opus 5.5), Codex (Sol), Gemini (Argon 4.6) и Devin (SWE). Это проверка на конкретных задачах, а не гарантия поведения в любой программе.

## Как работает

1. Уточняет желаемый результат, ограничения и уже испробованные варианты.
2. Ищет разные способы решения, похожие случаи и практический опыт.
3. Читает оригиналы, полезные ссылки из обсуждений, возражения, исправления и поздние итоги.
4. Проверяет актуальность и условия, при которых найденный опыт применим к вашей задаче.
5. Возвращает вывод со ссылками, существенными неопределённостями и следующим действием или тестом.

Если один инструмент не прочитал источник, ассистент пробует другой разрешённый маршрут. Поиск завершается, когда выполнена согласованная задача либо дальнейшая работа требует практического теста, доступа или решения пользователя. Полный охват интернета не обещается.

Перед новым исследованием скилл предупреждает об использовании выбранного в программе уровня усилий и ждёт ответа вроде «Продолжай». Повышенные режимы могут увеличить расход токенов. Сам скилл настройку не меняет. Дополнительные исследовательские агенты запускаются по запросу пользователя.

## Где полезен, а где избыточен

**Полезен**, когда нужно:

- найти готовые подходы и опыт похожих проектов;
- разобраться в ограничениях инструмента, дефекте или причинах отказа от метода;
- сравнить решения с учётом версий, условий и реальных результатов;
- разобрать доклад или лекцию, отделив подтверждённые выводы от предложений;
- найти следующий проверяемый шаг, если обычный поиск даёт повторяющиеся ответы.

**Избыточен** для перевода, переформулировки текста, простого факта, известной команды или небольшой правки, для которой внешнее исследование не требуется. Для новостных сводок и отслеживания трендов лучше использовать обычный поиск.

## Как установить

Нужна программа с поддержкой навыков и инструментами для чтения источников. Отдельный обязательный поисковый сервис не требуется.

1. Скачайте `digdeep-2026.10.17-r5.zip` со страницы **Releases** этого репозитория и распакуйте его, либо возьмите папку `digdeep` из самого репозитория.
2. При обновлении сохраните прежнюю папку `digdeep` для возможности отката.
3. Скопируйте **всю папку `digdeep`** в выбранное место; лишнего уровня `digdeep/digdeep` быть не должно. Для загрузки через интерфейс Claude используйте ZIP целиком, как описано ниже. Файлы README, TODO и папка `tests` в установленный скилл не нужны.
4. Откройте новую сессию и проверьте, что ассистент видит навык и читает версию `2026.10.17-r5` из `SKILL.md`.

### Codex, Antigravity App/IDE и Claude Code

Пути для Windows:

| Программа | Для всех ваших проектов | Для одного проекта |
|---|---|---|
| Codex | `%USERPROFILE%\.agents\skills\digdeep` | `<проект>\.agents\skills\digdeep` |
| Antigravity App/IDE | `%USERPROFILE%\.gemini\config\skills\digdeep` | `<проект>\.agents\skills\digdeep` |
| Claude Code | `%USERPROFILE%\.claude\skills\digdeep` | `<проект>\.claude\skills\digdeep` |

`%USERPROFILE%` — папка пользователя Windows; этот путь можно вставить в Проводник. В Linux/macOS пользовательские пути: `~/.agents/skills/digdeep` для Codex, `~/.gemini/config/skills/digdeep` для Antigravity и `~/.claude/skills/digdeep` для Claude Code.

Явный вызов: `$digdeep` в Codex, `/digdeep` в Claude Code и Antigravity App. Навык также может выбираться автоматически по описанию или явному упоминанию `digdeep` в запросе. Если навык не появился, проверьте путь к `digdeep/SKILL.md` и перезапустите программу (или откройте новую сессию).

Для Antigravity CLI пользовательский путь отличается: `~/.gemini/antigravity-cli/skills/digdeep`; путь внутри проекта тот же — `.agents/skills/digdeep`.

### Claude через веб-интерфейс или Desktop

В интерфейсе с разделом **Customize → Skills** выберите **+ → Create skill → Upload a skill**, загрузите `digdeep-2026.10.17-r5.zip` целиком и включите добавленный скилл. Для доступности Skills должна быть включена возможность **Code execution and file creation**; в управляемом аккаунте действуют настройки организации.

В архиве уже находится единственная папка `digdeep` с `SKILL.md` внутри. Перепаковывать ZIP или добавлять в него README не требуется. Простое прикрепление архива к сообщению не подтверждает установку скилла. См. [инструкцию Claude](https://support.claude.com/en/articles/12512180-use-skills-in-claude) и [требования к ZIP](https://support.claude.com/en/articles/12512198-how-to-create-custom-skills).

### Devin

Добавьте папку `digdeep` в `.agents/skills/` репозитория, доступного Devin, и сохраните её в репозитории. Итоговый путь: `.agents/skills/digdeep/SKILL.md`. Начните сессию с актуальной версией репозитория. Явный вызов: `@skills:digdeep`.

Способы установки: [Codex](https://learn.chatgpt.com/docs/build-skills#where-codex-loads-local-skills), [Antigravity](https://antigravity.google/docs/skills), [Claude Code](https://code.claude.com/docs/en/skills), [Devin](https://docs.devin.ai/product-guides/skills). Проверено по документации 17–18.10.2026; документированный способ установки сам по себе не подтверждает поведение скилла в каждой программе.

### Необязательный скрипт

Для `scripts/sources.py` нужен Python 3.12+. Он читает некоторые публичные API, ленты и страницы; без него ассистент может использовать другие доступные инструменты. Навык не привязан к Windows.

Для получения субтитров YouTube этим скриптом дополнительно нужен `yt-dlp`. При необходимости установите его в выбранное окружение Python:

```text
python -m pip install --user yt-dlp
```

Зависимости автоматически не устанавливаются. Отсутствие `yt-dlp` не исключает чтение субтитров через браузер или авторский текст.

Без токена запросы скрипта к GitHub API ограничены 60 в час на IP-адрес. Если у вас установлен [GitHub CLI](https://cli.github.com/) и выполнен вход, можно задать токен на время сеанса и запустить ассистента из того же окна терминала:

```powershell
$env:GITHUB_TOKEN = (gh auth token)
```

В bash: `export GITHUB_TOKEN="$(gh auth token)"`. Скрипт берёт `GITHUB_TOKEN` или `GH_TOKEN` из окружения и передаёт его только в `api.github.com`. Скилл токен не запрашивает и не сохраняет; задавать его или нет — решение пользователя.

## Ограничения

- Результат зависит от модели, доступных инструментов и прав доступа. Скилл не гарантирует нахождение ответа, полноту поиска или отсутствие ошибок.
- Публичные API, RSS и страницы могут меняться, ограничивать запросы и отдавать только часть обсуждения. Доступность Reddit и субтитров YouTube проверяется для конкретного материала.
- Reddit объявил отключение RSS-лент 13.11.2026. Команда скрипта `reddit-search` опирается на RSS, а `reddit-thread` сейчас читает треды только через запасной путь RSS: после этой даты обе, вероятно, перестанут работать. Другие маршруты к Reddit ассистент выбирает сам.
- В ограниченной среде сетевому скрипту может потребоваться штатное разрешение на доступ. Ошибка одного маршрута не доказывает недоступность источника всеми способами.
- Вход, платный доступ, CAPTCHA и запреты программы не обходятся. При необходимости ассистент просит выполнить разрешённое действие; пароли и экспорт cookies ему передавать не нужно.
- Чужой опыт и заявленная возможность не равны проверке на ваших данных. Перед существенными затратами или изменением рабочего процесса нужен подходящий практический тест.

## Если в Windows искажается кириллица

Если русский текст из файлов скилла возвращается через PowerShell в виде нечитаемых символов, проверьте кодировку вывода процесса. В проверенном случае PowerShell правильно читал UTF-8, но выдавал CP866, которую принимающий инструмент интерпретировал как UTF-8.

Перед командой чтения можно явно задать UTF-8 для вывода:

```powershell
[Console]::OutputEncoding = [Text.UTF8Encoding]::new($false)
```

При чтении файла используйте `Get-Content -LiteralPath <путь> -Encoding UTF8`. Параметр чтения и [кодировка консольного вывода](https://learn.microsoft.com/en-us/dotnet/api/system.console.outputencoding) решают разные задачи. Файлы скилла уже сохранены в UTF-8; перекодировать их не требуется.
