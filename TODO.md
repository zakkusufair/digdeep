# DigDeep — идеи для следующих версий

Зафиксировано: 17.10.2026, пересмотрено 19.10.2026. Базовая версия: `2026.10.17-r5`.

Статус: направления для будущего рассмотрения. Изменения не реализованы, выигрыш не измерен, если не сказано иное. Это не список неисправностей текущего релиза.

Рабочая позиция: если скилл выполняет задуманный сценарий, сохранять его поведение. Менять его при воспроизводимом расхождении с замыслом либо после проверки пользы новой возможности. Не увеличивать основной текст ради дополнительных общих напоминаний.

Пробы доступа ниже — один запрос `curl` без ключа в указанную дату. Это наблюдение, а не гарантия: перед использованием маршрут проверяется заново.

## 1. Reddit после 13.11.2026 — срок известен

**Основание.** Reddit объявил отключение RSS-лент на 13.11.2026. `reddit-search` целиком опирается на RSS. `reddit-thread` сначала пробует HTML old.reddit, но в проверках 13–18.10.2026 получал страницу «Welcome to Reddit» и читал треды только через запасной путь RSS.

**Кандидат на замену.** Архив Arctic Shift: `arctic-shift.photon-reddit.com/api/posts/search` 18.10.2026 ответил 200 и вернул JSON; 13.10.2026 тот же сервис давал таймауты. Это сторонний архив с неполным и запаздывающим охватом, а не Reddit. Копию так и помечать: архив, с датой снимка.

**Критерий полезности.** На реальной задаче найден и прочитан тред, недоступный другими разрешёнными маршрутами, с явной пометкой источника копии.

## 2. Глубина чтения в версиях r4 и r5 — открытый вопрос

- [ ] Выяснить, сокращают ли изменения r4/r5 глубину чтения, и при подтверждении исправить причину.

**Наблюдение (18–19.10.2026, Claude Code, Opus 5.5, xhigh, один и тот же вопрос).** Метрики посчитаны скриптом по журналам сессий.

| Прогон | Версия | Уникальных страниц | Переходов по ссылкам из прочитанного |
|---|---|---|---|
| A5 (13.10, другое подключение Exa) | r3.1 | 34 | 8 |
| A7 | r3.1 | 25 | 5 |
| A6 | r5 | 13 | 0 |
| A8 | r5 + формулировки остановки из r3.1 | 14 | 1 |

Точность A6 по сверке 18 утверждений с первоисточниками: 15 подтверждено, 3 частично, 0 неверных. Каждый прогон нашёл свои решающие источники; ни A6, ни A8 не нашли датасет, который нашёл A7.

**Что уже исключено.** Возврат трёх формулировок остановки из r3.1 (A8) глубину не вернул.

**Подозрение.** Предупреждение об уровне усилий, появившееся в r4: инструкция модели говорит о росте расхода токенов, а справочник — о том, что `xhigh` должен оправдывать стоимость. Это может настраивать на экономию вопреки фразе «не сокращать объём». Альтернатива — обычный разброс: на каждую версию 1–2 прогона.

**Как проверить.** Две версии r5, отличающиеся только текстом предупреждения: нынешний и нейтральный, без упоминания расхода токенов в инструкции модели (предупреждение пользователю остаётся). По два прогона на версию на одном вопросе в одинаковых условиях. Сравнивать уникальные страницы, переходы по ссылкам, решающие находки и точность по сверке. Порядка $6 за прогон по `total_cost_usd`.

**Критерий.** Нейтральная версия устойчиво (в обоих прогонах) читает глубже без потери точности — тогда менять текст. Иначе считать разбросом и закрыть вопрос.

## 3. Предупреждение об уровне усилий иногда пропускается

**Наблюдение.** Предупреждение прозвучало в 11 из 12 запусков (T2 — 10/10, A6 — 1/1). В A8 модель на запрос «Используй digdeep» с подробной задачей сразу начала поиск.

**Условие.** При частоте сбоя около 1/12 доказать пользу правки можно только десятками прогонов. Вносить вместе с другой правкой этого раздела (см. п. 2) и проверить, что предупреждение не стало повторяться на продолжениях.

## 6. Чтение и доставка найденного материала

### Комментарии ревью PR и GitHub Discussions

- [ ] На подходящем реальном случае проверить, нужен ли отдельный маршрут helper.

**Основание.** Нынешний `gh-thread` не получает комментарии ревью к строкам кода и GitHub Discussions; ограничение документировано. Комментарии ревью доступны через REST без токена ([pull request review comments](https://docs.github.com/en/rest/pulls/comments)). Discussions есть только в GraphQL, а GraphQL требует токен: без `GITHUB_TOKEN` остаются браузер и чтение страниц.

**Критерий полезности.** Получен решающий фрагмент, отсутствовавший в прежнем чтении; частичная загрузка обозначена явно.

### Большие результаты helper

- [ ] Сначала выяснить, нужна ли запись результата в файл в средах, кроме Claude Code.

**Основание.** Ограничение размера отдельного тела не ограничивает суммарный stdout. Claude Code сам сохраняет крупный вывод инструмента в файл (наблюдалось 18.10.2026), так что для него польза мала. Для Codex и других сред не проверено.

**Критерий полезности.** В длинном обсуждении доступен поздний итог или исправление автора, файл сохраняется без потерь, а непоказанные фрагменты не объявляются прочитанными.

## 7. Поиск по связям публикаций

- [ ] Проверить OpenAlex или подходящий дисциплине аналог как маршрут от найденной публикации к её источникам и последующим работам.

**Основание.** Переходы по ссылкам уже предусмотрены скиллом; улучшение — практический маршрут для случаев, когда обычный поиск повторяет несколько популярных названий.

**Доступ.** По [справке OpenAlex](https://help.openalex.org/how-to-use-the-api/rate-limits-and-authentication) (обновлена 15.10.2026) базовые запросы работают без ключа в пределах дневного бюджета, а листать дальше первой страницы можно только с бесплатным ключом. Скилл ключ не просит, только берёт из окружения, если пользователь его задал. Semantic Scholar 18.10.2026 без ключа ответил 429 — как маршрут без ключа ненадёжен.

**Границы.** Связи и метаданные служат для обнаружения; оригиналы читаются отдельно; число цитирований не подтверждает вывод; списки ссылок могут быть неполными ([OpenAlex о цитированиях](https://help.openalex.org/data/works/citations/)).

**Критерий полезности.** Найдена и прочитана существенная последующая работа или альтернатива, влияющая на вывод или план теста.

## Не добавлять без новых фактов

- TGStat и 4PDA: 18.10.2026 оба ответили 403 от защиты от ботов; явное упоминание заставит модель стучаться в закрытое.

## Как принимать решение о включении

Начать с одной небольшой правки и конкретной задачи. Заранее назвать проверяемую неопределённость и результат, оправдывающий добавление. Сохранить первый результат, ошибки и ограничения. Один удачный пример не объявлять доказательством общего превосходства или экономии токенов.

Новые маршруты должны расширять возможности поиска. Не превращать их в обязательный обход всех сайтов, зависимость от одного сервиса или требование применять helper в каждом исследовании.
